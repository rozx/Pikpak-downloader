# PikPak 独立授权验证

这是 OpenSpec 任务 1.1–1.3 的隔离验证入口，使用官方 OpenID 发现配置中的动态注册和授权码端点。它不安装、执行或借用官方 CLI 的登录状态，也不使用现有应用的客户端身份冒充本工具。

公开依据：[官方 OpenID 发现端点](https://user.mypikpak.com/.well-known/openid-configuration)、[OpenID Connect 动态注册规范](https://openid.net/specs/openid-connect-registration-1_0.html)。发现文档存在不保证匿名客户端注册、全部所需权限或真实登录一定可用，均需实际验证。

## Run

目前仅在已验证系统凭据能力的 macOS 上启动：

```sh
bun install --frozen-lockfile
bun run typecheck
bun test
bun run start
```

打开本机 `http://127.0.0.1:53682`，点击前往 PikPak 登录。账号密码只在 PikPak 官方页面输入；此程序不提供账号密码输入框。

程序用自己的名称注册原生客户端，使用精确 loopback 回调、PKCE S256 和一次性 state。客户端秘密、访问/刷新令牌和会话引用写入系统凭据库，服务名为 `com.rozx.pikpak-downloader.verification`，不会写入项目目录。再次启动复用本程序的客户端注册记录；它不会枚举其他凭据。

授权后检查账号身份、刷新后身份一致性和容量接口是否可读。页面与 `/status` 只显示结果和脱敏错误；不输出授权码、令牌、账号资料或服务端错误原文。重启可以复用本工具已保存的会话并重新核对身份。

身份验证通过后，本地页面提供独立的验证资料表单。它通过同源 POST 将规范化资料直接存入系统凭据库，绑定当前账号；不回显，也不写入项目、命令参数或日志。后续验证程序仅使用此受保护引用。

## Disposable Folder Check

`bun cloud-probe.ts` 验证最小云端写入能力：创建两个随机命名的空测试目录，在精确身份和活跃/回收站子项均为空的检查后，定向永久删除目标目录，确认对照目录仍在，再清理对照目录。归属与操作进度放在本应用系统凭据库中；运行结果只包含计数、布尔值和脱敏错误，不接受任意文件 ID。

未知创建结果不会自动重试；出现权限或删除核对问题时保留记录，不扩展清理范围。已完成的检查再次运行只读取自身记录，不重复创建目录。

## Limits

- 已验证登录、刷新、容量、一次单文件转存和临时空目录定向删除。真实嵌套、原分享失效恢复及完整故障场景保留任务 8.2；未知提交结果不重试的保护已有合成测试。
- 本地授权服务本身不创建或删除云端文件；独立的 `cloud-probe.ts` 只处理本次创建并有归属记录的空测试目录。
- 若动态注册或权限被拒绝，保留脱敏原因；不能把 OpenID 登录成功等同于完整云盘授权。
- Windows 凭据适配与发布验证仍独立进行。
- Ctrl+C 关闭本地服务；已授权的本程序凭据保留在系统凭据库，便于后续验证。可以从 PikPak 的已连接应用中撤销授权。

## Share and Restore Checks

- `bun share-probe.ts` 从受保护记录读取测试资料，检查根目录、分页和子目录元数据，最多进行 30 次读取请求。只输出计数和能力标记，并把选定文件的信息保存到系统凭据库；有请求上限时明确报告扫描不完整。
- `bun restore-probe.ts` 在容量和源元数据核对后仅提交一次单文件转存，保存意图及服务端任务标识，再核对任务结果与目标元数据。未知提交结果不会自动重发，副本保留供后续验证。
- `bun direct-link-probe.ts` 只检查分享文件是否提供原始下载地址；若地址和元数据均满足检查，只向官方 HTTPS 下载主机请求一个字节，不落盘内容。当前样本未返回原文件直链，未改变转存方案。

2026-10-08 的实际运行已满足 G1 和用户确认的 G2 开发前范围，但各单项程序不独自代表整个验收。模拟测试使用公开合成数据，不包含真实验证资料。

## Content Checks

`bun download-probe.ts` 已实际验证转存副本的原始下载入口、HTTPS、206 范围与大小、读取前后元数据一致。`bun full-content-probe.ts` 进一步按首段 1 MiB、后续最多 8 MiB 的范围顺序读取整份副本，每段重新查询元数据与原始地址，最后校验 GCID 并计算本地 SHA-256。仅输出进度与布尔值；摘要记录写入系统凭据库，内容流式丢弃，**不构成本地交付，不产生清理资格**。

GCID 的分块规则核对自 [rclone 的 PikPak 实现](https://github.com/rclone/rclone/blob/master/backend/pikpak/helper.go#L338)：分块从 256 KiB 开始，文件超过 512 块时倍增至最多 2 MiB；对各非空块求 SHA-1，再对拼接的原始摘要求 SHA-1。空内容是 SHA-1 空字节的结果。它不是普通整文件 SHA-1，也不能用抽样 CID 代替完整内容校验。

`gcid.test.ts` 使用独立 Python hashlib 黄金向量与碎片化输入覆盖边界。`content-transfer.test.ts` 验证大小与 GCID 绑定、改名不产生内容版本、同大小替换、零字节、下载中版本变化、地址过期后的有界刷新、错误/压缩/截断响应和多段完整覆盖。所有 CDN 请求不发送账号 Authorization，拒绝重定向及非官方 HTTPS 地址。

`bun rename-probe.ts` 已实际对受保护转存记录指向的测试副本进行临时改名，确认大小与 GCID 不变后恢复原名。恢复意图保存在系统凭据库，遇到未知名字或内容变化时不擅自覆盖。

转存映射仅采用已验证的 `trace_file_ids` 精确键，不以任务的笼统 `file_id` 猜测。互相矛盾的映射保留核对状态，不认领任一目标。

当前共有 41 项隔离测试及独立类型检查通过。真实完整运行经过 29 段读取和 28 次重新获取地址，最终版本稳定且 GCID 比对通过；记录只保存在受保护存储。过期响应、零字节和同大小替换/中途变更场景属于合成契约测试，不能称为账号实测。

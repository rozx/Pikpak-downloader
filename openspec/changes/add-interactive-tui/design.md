# Design

## Context

`add-clipboard-download-workflow` 已实现前台 `watch`：`foregroundLoop`（`src/runtime/watch.ts`）并行运行剪贴板轮询和 `Engine.step` 循环，事件经 `printEvent` 逐行打印。进度事件每秒一次，仅含百分比。重试、取消由独立命令在停止监听后写任务库；暂停只有系统原因，存于每账号一条的 `pauses` 表。任务库 `config` 表已保存 `active_account` 与 `output_root`，watch 每次启动都会写入当前目录。项目当前没有运行时依赖。

2026-10-14 首次在 Windows 实际运行时确认：进度刷屏、只显示 ID、无法在运行中操作任务。用户在评审中确认的选择：全屏任务面板；面板内可重试、取消、暂停队列、查看详情、打开目录；设置继续存任务库；剪贴板监听加手动粘贴；采用 Ink；先出彩色效果图（已确认，见下文"界面布局"）。

## Goals / Non-Goals

**Goals:**

- 不带参数即可完成登录检查、目录设置、接收分享、观察进度和处理任务。
- 面板操作与执行器严格串行，不放宽现有的单实例、未知操作核对、取消保留资源等规则。
- 纯文本 `watch` 与全屏界面共用同一个运行时，只是事件呈现方式不同。

**Non-Goals:**

- 多连接分段下载、鼠标、主题、Linux、后台服务、多账号、界面内密码登录。
- 改变下载、校验、回收、扫描与提取码配对规则。

## Decisions

### 1. Ink 作为渲染层，以打包验证为第一道门槛

按用户选择采用 Ink（React 终端渲染）。它带来现成的输入处理、flex 布局和 `ink-testing-library`；代价是首批运行时依赖（`ink`、`react` 及其布局依赖）和更大的产物体积。

实施第一步是隔离验证程序 `spikes/tui-ink/`：在 `bun build --compile` 的 `bun-darwin-arm64`、`bun-darwin-x64`、`bun-windows-x64`、`bun-windows-arm64` 目标下编译含输入框和列表的最小界面，并在 Windows Terminal、Windows 传统控制台、macOS 终端实测原始按键、多行粘贴不触发提交、窗口缩放、备用屏幕进出、中文宽度对齐与 Ctrl+C 处理。验证通过后锁定版本写入锁文件；不通过则回到方案评审，不在业务代码中绕过。

### 2. 模块划分

| 模块 | 职责 | 不负责 |
| --- | --- | --- |
| `src/runtime/session.ts`（由 `foregroundLoop` 提取） | 持有 Engine、剪贴板轮询、手动输入、命令队列、当前步骤中断控制和事件分发 | 任何呈现 |
| `src/runtime/watch.ts` | 纯文本订阅者：把事件转成限频的文本行 | 调度 |
| `src/tui/app.tsx` | Ink 根组件、页面路由、按键分发 | 直接写任务库 |
| `src/tui/screens/*` | 启动检查、登录、目录设置、主面板、详情、设置、粘贴、确认框 | 业务规则 |
| `src/tui/view-model.ts` | 纯函数：任务库快照 + 运行时事件 → 行列表、计数、折叠与滚动状态 | I/O |
| `src/tui/format.ts`、`speed.ts`、`theme.ts` | 大小与时长格式、按显示宽度省略、5 秒滑动窗口速度与剩余时间、16 色映射和 `NO_COLOR` | — |
| `src/cli.ts` | 无参数且交互终端时启动界面，否则保持现有分派 | — |

界面只通过运行时会话提交命令、通过任务库只读查询取数据，便于 view-model 和格式化函数做纯单元测试。

### 3. 启动状态机

```
checking ─┬─ 执行锁被占用 ───────────────▶ busy（任意键退出）
          ├─ 无可用会话 ────────────────▶ login ──授权成功──┐
          ├─ 目录缺失或不可写 ───────────▶ setup ──保存成功──┤
          └─ 全部满足 ──────────────────────────────────────┴▶ main（启动运行时会话）
```

登录页调用现有 `login()`，把其提示回调接到界面状态；浏览器打不开时显示本地入口地址。Esc 取消会停止本地回调服务。目录页复用 `config --output` 的校验（存在、目录、可写可进入）。

### 4. 命令队列与步骤中断

运行时会话为每次 `Engine.step` 创建独立 `AbortController`，与全局退出信号合并后传入。会话根据 `scanning`、`saving`、`downloading` 事件记录当前执行项（分享 ID 或文件 ID）。

界面提交的命令：`retry`、`cancel`、`pauseQueue`、`resumeQueue`、`submitText`、`setOutputRoot`、`setClipboardWatch`。主循环在两次步骤之间按顺序处理命令；若命令是 `pauseQueue`，或是针对当前执行项（或其所属分享）的 `cancel`，先中断当前步骤并等待其返回，再写任务库，最后唤醒调度。中断走与 Ctrl+C 相同的路径：已保存的断点、转存与删除的未知结果核对规则保持不变。

这样满足现有"可能与执行冲突的修改操作 SHALL 被串行化"的要求，并让界面中的取消不必先停止监听。独立的 `cancel`、`retry` 命令在界面运行时仍因执行锁被拒绝，行为不变。

### 5. 用户暂停与配置键

用户暂停存为 `config` 表的 `queue_paused`，不写入 `pauses` 表，避免与系统暂停互相覆盖。`Engine.step` 在现有系统暂停检查之外读取该键。剪贴板监听开关存为 `clipboard_watch`（缺省视为开启）。`Store.setConfig` 和 `config` 的键类型相应扩展；表结构不变，无需迁移。

### 6. 进度事件与刷新节奏

进度事件改为 `{ type: "progress", id, bytes, size }`，每秒最多 4 次。速度取最近 5 秒样本的平均值，样本不足 2 秒或速度低于 1 KiB/s 时不显示剩余时间。纯文本订阅者只在进度跨过 10% 整数倍或间隔满 30 秒时输出。

任务库新增只读查询，按分享列出文件的 ID、相对路径、大小、状态、重试次数、取消标记、最近错误、断点字节和云端副本状态。界面在收到事件或每 500 ms 刷新快照（取较晚者），渲染不超过每秒 10 次。云盘容量每 60 秒及回收事件后刷新，本地剩余空间每 30 秒刷新。

### 7. 界面布局与颜色

主面板自上而下：标题栏（账号、云盘、本地空间、剪贴板、暂停横幅）→ 按分享分组的文件列表 → 最近事件 → 按键提示。只用标准 16 色：

| 含义 | 图标 | 颜色 |
| --- | --- | --- |
| 已完成、已登录、监听中 | ✓ ● | 绿 |
| 下载中、进度条、速度 | ↓ █ | 青 |
| 转存中 | ⇡ | 蓝 |
| 扫描中 | ⟳ | 品红 |
| 暂停、等待、按键提示 | ⏸ ⌛ | 黄 |
| 失败 | ✗ | 红 |
| 排队、已取消、次要信息 | · ⊘ | 灰 |
| 标题栏、选中行 | — | 蓝底 |

列宽按终端显示宽度计算，过长名称中间省略。窗口小于 60×15 时只显示放大提示。文件名只显示在本机屏幕上，不写入日志；提取码和凭据从不显示。

### 8. 退出与终端恢复

q 与 Ctrl+C 触发有界停止并显示"正在停止并保存进度"；停止期间再次 Ctrl+C 立即退出。Ink 卸载之外，另在进程退出、`SIGTERM`、`SIGHUP` 和未处理异常时写入恢复序列（退出备用屏幕、显示光标、关闭原始输入模式），然后在主屏幕打印会话摘要或 `publicError` 的用户说明。

## Risks / Trade-offs

- Ink 在 Bun 独立产物和 Windows 控制台中的兼容性未知 → 决策 1 的打包验证作为门槛，失败即回到评审。
- 首批运行时依赖增加供应链与体积 → 锁定版本、只引入 Ink 及其必需依赖，验证后记录产物体积。
- 中断当前步骤可能暴露尚未覆盖的中断点 → 中断沿用 Ctrl+C 已测试的路径，并新增"下载中途、转存提交前后、扫描翻页中"的中断测试。
- 高频进度导致 React 重渲染开销 → 事件限频、快照合并、行组件按 ID 记忆化。
- 传统控制台字体对部分中文或图标宽度处理不一致 → 在验收中记录，必要时提供 ASCII 图标回退。

## Migration Plan

任务库结构不变，仅新增 `config` 键；旧版本读取到未知键时忽略。回退时移除界面入口即可，`watch` 与子命令不受影响。本变更须在 `add-clipboard-download-workflow` 归档后归档。

## 打包验证

### 1.1 编译结果（2026-10-14）

验证程序 `spikes/tui-ink/` 使用 Ink 8.0.0、React 19.3.1、Bun 1.4.2，在 Windows 11 x64 开发机上交叉编译四个目标全部成功：

| 目标 | 产物体积 |
| --- | --- |
| `bun-darwin-arm64` | 60.5 MiB |
| `bun-darwin-x64` | 67.3 MiB |
| `bun-windows-x64` | 83.2 MiB |
| `bun-windows-arm64` | 75.1 MiB |

同一 Bun 版本下现有业务 CLI 的 windows-x64 产物为 82.3 MiB，Ink 与 React 约增加 1 MiB。

验证中确定的构建约束：

- Ink 静态导入可选依赖 `react-devtools-core`（仅 `DEV=true` 时使用）。`--external` 不可行：Bun 把外部 import 提升到产物顶层，独立产物启动即因找不到该包退出。构建必须改用 `Bun.build`，以插件把它解析为无副作用的空实现。
- 独立产物默认读取运行目录下的 `.env` 与 `bunfig.toml`，构建时关闭 `autoloadDotenv` 与 `autoloadBunfig`，避免用户目录中的文件改变程序行为。
- Bun 1.3.8 不提供 `bun-windows-aarch64` 目标；开发与发布构建必须使用 `packageManager` 声明的 Bun 1.4.2。
- 经 `Bun.build` 编译的独立产物中，入口模块的 `import.meta.main` 为 false（命令行 `bun build --compile` 为 true）。依赖该判断的 `src/cli.ts` 不能直接作为编译入口；发行构建使用无条件执行的 `src/main.ts`，`bun src/cli.ts` 的开发用法保持不变。

windows-x64 产物已在 Claude Code 终端面板启动：中日韩名称按显示宽度中间省略，进度条刷新正常，Ctrl+C 第一段进入停止状态并在退出后恢复原屏幕。省略后的名称会填满整列，正式界面的列之间需保留 1 列间隔。

### 1.2 终端实测

- Windows（2026-10-14）：用户按 `spikes/tui-ink/README.md` 清单实测 windows-x64 产物，报告全部通过。
- macOS：待实测，作为发布门槛保留。

用户反馈验证界面的观感不及效果图。验证程序随后增加 `mock.tsx`，用 Ink 按确认的六张效果图绘制主面板、暂停与取消确认、详情、粘贴框、设置和登录页，用于在真实终端中对比颜色、蓝底选中行、圆角边框和列宽自适应。

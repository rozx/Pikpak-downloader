# Proposal

## Why

用户希望能同时下载多个文件，并在设置中配置同时下载的文件数；据用户经验，免费账号最多 1 个、会员最多 5 个（尚未实测）。现有设计（`add-clipboard-download-workflow` 设计 §3）只有一个执行器，同一时刻最多一个转存或下载流水项。一个分享里有许多小文件时，它们只能逐个排队；而 2026-10-15 的 P1 实测表明 CDN 按单个连接限速，每个连接约 31–65 KiB/s，多开连接才能提高合计速度。`add-parallel-segment-download` 解决单个大文件的速度，本变更解决多个文件排队的问题。§3 同时规定，以后增加并发必须显式引入云端容量预留，不能只是增加同时执行的 Promise。

## What Changes

- 新增配置“同时下载的文件数” `max_active_files`，范围 1–5，默认 1（保持现状）。全屏界面设置页、`config --files <1-5>` 与 `status` 都可查看或修改，新值在当前文件结束后生效。
- 按账号等级限制：免费账号实际上限为 1，会员最多 5。等级读取方式与这两个上限都要先由真实账号实测确认（验证门槛 P3）；确认前不放开超过 1 的值。
- 执行器从“单流水项”改为“有界并发的下载阶段”：扫描与转存仍然串行；已转存的文件最多 N 个同时下载，每个文件仍用自己的临时文件、检查点和云端副本。
- 云端容量预留：同时在途的 N 个文件各自持有一份云端副本，空间计划必须为在途副本预留容量，回收资格不变（未交付的副本不能回收）。
- 连接按文件计算：每个在途文件各自使用连接数设置（最多 8 个），不因同时下载的文件数而减少（用户实测后要求，替换了最初的全局 8 连接预算）。
- 运行时会话与界面：会话为每个在途文件维护各自的中断控制器，取消和暂停只中断目标文件；主面板同时显示多行下载进度，标题栏显示在途文件数与合计速度。

不包含：并发扫描或并发转存、跨账号并发、跨文件的连接预算、按文件大小自动调整并发。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `transfer-queue`：单执行器、同一时刻一个流水项，改为有界并发的下载阶段，并增加在途文件的取消与暂停语义。
- `cloud-space-reclamation`：空间计划为同时在途的多个副本预留容量。
- `share-downloads`：每个在途文件独立使用连接数设置。
- `terminal-ui`：设置页新增“同时下载的文件数”，主面板支持多个文件同时显示进度。

## Impact

- 顺序：用户已确认先完成 `add-parallel-segment-download` 的第 3–5 组，再实施本变更；两者都改 `src/runtime/engine.ts` 的下载路径，本变更建立在分段下载之上，并复用其连接数配置和共享地址租约。
- 代码：`src/runtime/engine.ts`（调度与在途文件集合）、`src/runtime/session.ts`（每文件中断控制器）、`src/pikpak/space.ts`（容量预留）、`src/state/store.ts`（`max_active_files` 配置键；如需持久化预留则增加结构字段）、`src/cli.ts`、`src/tui/`。
- 外部服务：同时在途的云端副本最多 5 份；CDN 连接总数最多为 N × 每文件连接数（上限 40），超过 P1 验证过的 8 个，由 P3b 验证是否触发限流。
- 数据：默认值 1 时行为与现在一致，可随时设回 1。

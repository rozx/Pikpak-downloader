# Proposal

## Why

用户实测全屏界面后反馈三个问题：

1. 只有 `p` 暂停或继续整个队列，不能单独暂停某个文件或分享，也没有明确的“全部开始”。
2. 任务运行时，设置页的修改看起来不生效。原因是运行时会话只在两次执行步骤之间处理命令；同时下载数为 1 时，一个步骤就是一个文件的完整下载，修改下载目录、连接数、同时下载数或剪贴板开关，要等当前文件下载完才写入。粘贴分享、取消排队中的文件也受同样影响。
3. 已完成或暂停的任务占着 PikPak 云端副本，没有办法立刻释放空间；自动回收只在下一个文件需要空间时才发生。

## What Changes

- 命令立即生效：除“暂停整个队列”以及针对当前串行步骤中文件的暂停或取消之外，所有会话命令都按提交顺序立即执行，不等当前步骤结束。只有需要先中断正在执行的工作的命令，才先中断并等它在安全点停止。
- 单项暂停：文件和分享都可以单独暂停与继续（新按键 `p`）；暂停状态持久化，重启后保持。暂停分享会停止它的扫描和所有在途文件。
- 全部暂停与全部开始：新按键 `P`。有任何暂停（队列或单项）时它表示“全部开始”，清除队列暂停和全部单项暂停；否则表示“全部暂停”。按键提示始终写明当前会执行的操作。
- 手动释放云端副本：新按键 `x`，经确认后立即永久删除所选文件（或分享内全部合格文件）在 PikPak 中由本工具创建的云端副本。只针对本工具创建且有归属证据、当前没有在下载的副本；未完成的文件之后继续时会从分享重新转存，确认框说明这一点和分享失效的后果。服务端拒绝（如没有永久删除权限）时只提示原因，不暂停账号。手动释放与自动回收共用同一把云端操作锁，不会重复删除。

不包含：从任务列表中删除记录、批量选择、删除本地已下载文件、回收站（trash）操作。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `transfer-queue`：单项暂停与恢复、全部开始；命令立即生效。
- `cloud-space-reclamation`：用户手动释放云端副本与全部释放；已完成任务释放后删除记录。
- `terminal-ui`：新按键 `p`（此项）、`P`（全部）、`x`（释放云端副本）与 `X`（全部释放），设置在运行中立即生效；任务位置图标、按下载目录分组、释放中状态、任务名称去掉后缀。
- `share-downloads`：任务目录以去掉后缀的任务名称命名，临时文件放在目标旁边，不再建立暂存目录（2026-10-15 用户反馈后加入）。

## Impact

- 代码：`src/state/schema.ts` 与 `src/state/store.ts`（结构版本 5：`files.paused`、`shares.paused`；暂停、恢复、手动释放的查询与写入）；`src/runtime/session.ts`（命令立即执行与中断规则）；`src/runtime/engine.ts`（跳过暂停项、云端操作锁、手动释放）；`src/pikpak/space.ts`（手动释放的删除与核对，静默请求）；`src/download/workspace.ts`（打开期间分享被改目录时按新目录重开）；`src/tui/`（按键、提示、确认框、状态显示）。
- 数据：任务库结构升到 5，沿用升级前备份；旧程序拒绝写入。
- 外部服务：手动释放会调用 `files:batchDelete`。2026-10-15 用户实测确认现有授权允许永久删除（见 design.md）；服务端拒绝时功能只会提示原因。
- 依赖：建立在 `add-interactive-tui`、`add-concurrent-file-downloads` 的会话与下载池之上。

# 复制分享文本

复制一次完整文本，让链接与提取码同时出现在同一快照中。以下仅为合成格式示例，没有真实资源：

```text
链接：https://mypikpak.com/s/synthetic-one
密码：demo
```

也支持链接内明确标记的 `pwd`、`password`、`passcode` 或 `pass_code` 参数；无码分享可以只复制链接。真实缺码、错误码分别已观察到 `PASS_CODE_EMPTY`、`PASS_CODE_ERROR`，应等待新的完整文本，不把它们当成全局账号失效。

多个分享可以分别占一行或一段，且每个码明确配对。一个码跟在多条无法区分的链接之后时不会猜测；请分别复制。相似域名、其他 PikPak 页面、单独的提取码和普通文本不会创建任务。原始剪贴板不写入日志或数据库。

看到任务 ID 的接收确认才表示资料与请求已保存。一次复制中部分分享保存失败时，已确认的分享保留，监听仅重试未确认部分。剪贴板是当前内容快照：快速复制可能覆盖尚未读取的内容，变化计数不能还原历史；未看到确认时请重新复制。

再次复制相同文本可以触发增量扫描；保持剪贴板不变不会不断扫描，也不会定时监视远端分享更新。完成且未变化的版本即使本地成果已移走，也不会自动重下；同名新版本保留旧成果。失败预算耗尽后，停止监听并用 `retry <任务ID>` 开启新的有限尝试周期；复制分享不会重置文件重试预算。

新分享在接收时固定下载根。更改默认目录仅影响新分享，已接收分享的后续文件继续使用原目录。`cancel` 保留资源和取消标记；即使旧文本还在剪贴板，也不会重新启动被取消的分享。

解析、持久接收及 `watch` 流程已实现。macOS 原生快照、独立测试剪贴板及编译后二进制的子进程读取已实测；读取隔离在子进程，故障不会同步阻塞下载主线程。Windows 原生桥接代码已加入，实际运行仍待任务 8.3。

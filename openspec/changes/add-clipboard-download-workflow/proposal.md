# Proposal

## Why

下载 PikPak 分享资源目前需要用户先转存到自己的云盘，再下载到本地，并在云盘容量不足时手动腾出空间。本项目把云盘作为中转空间，让用户启动监听后，通过复制分享文本完成这条流程。

## What Changes

- 提供独立运行的 macOS、Windows CLI；用户无需安装官方 PikPak CLI。`watch` 手动在终端前台运行，展示任务、下载和清理进度。
- 登录优先使用可用的官方浏览器授权；若独立客户端无法通过该方式取得所需能力，支持终端交互式账号密码登录，并复用会话令牌。
- 从一次剪贴板文本中识别分享链接及其提取码。缺码任务等待补充，不把后续单独复制的其他文本猜作提取码；无提取码分享正常处理。
- 持久化任务队列。再次复制同一分享时重新扫描，只下载新增或变化的文件，合并正在执行的工作；同名新版本保留为另一份本地文件。
- 按文件分批转存、等待就绪、下载和校验，支持分享总大小超过云盘容量的场景。单个文件无法容纳时说明原因并继续其他可执行文件。
- 仅在容量不足时，按本地下载完成时间从旧到新，定向永久删除本工具创建且已成功下载、校验的云端副本；释放足够容量即停止。历史下载成功记录决定清理资格，用户之后移动或删除本地文件不影响资格。
- 单文件失败有限重试后保留云端副本和本地进度，继续其他任务；登录失效、本地磁盘不足等全局问题暂停下载执行，监听仍可接收任务。
- 提供显式取消入口，让用户停止无法继续的任务并解除其执行阻塞；取消保留本地文件、云端副本及操作记录，不把未交付副本变成可清理对象。
- 先验证独立登录与删除权限、嵌套分享的逐文件转存与映射、版本识别与完整性校验。未经验证的接口能力不得作为已实现承诺。

首版设计默认：单个活动账号、可配置的本地下载目录、保留分享目录层级、单个转存/下载执行器。暂不包含后台服务、开机自启、多账号调度、Linux 发行版、云盘既有文件接管、本地自动清理或持续定时扫描分享。

## Capabilities

### New Capabilities

- `account-session`: 独立登录、会话保存与刷新、权限和账号身份隔离。
- `clipboard-intake`: 前台监听、完整分享文本解析、提取码补充与输入去重。
- `transfer-queue`: 持久化任务状态、增量扫描、故障隔离、暂停与恢复。
- `share-downloads`: 嵌套分享枚举、分批转存、可靠落盘、校验、续传和文件名冲突处理。
- `cloud-space-reclamation`: 云端容量判断、已完成副本回收资格、最旧优先定向清理和容量不足处理。
- `cli-runtime`: macOS/Windows 独立运行、配置、终端进度、任务操作与正常退出。

### Modified Capabilities

无。当前项目尚无业务规格或实现。

## Impact

- 新增系统剪贴板、凭据存储、PikPak 接口、下载传输、任务持久化和终端交互模块；现有仓库仅有许可证和 OpenSpec 初始化文件，无旧业务行为需要迁移。
- 依赖 PikPak 的分享、转存、文件查询、下载地址、存储容量、身份认证和定向删除能力；外部接口仍需实测，不能把社区实现视为官方兼容保证。
- 工具将创建云端中转副本、本地任务数据和下载文件，并按已确认规则删除自己管理的云端副本；不接管用户原有云端文件，不清空整个回收站，不删除本地成果。
- 本变更的当前交付仅为规划文档。后续实现从接口可行性验证开始，验证未通过时保留阻塞原因并修订方案。

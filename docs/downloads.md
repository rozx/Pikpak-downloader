# 下载、校验与恢复

分享在本地开始下载时固定下载根；分享目录与名称映射持久化。改变默认目录时，新分享和本地还没有任何内容的分享改用新目录，已开始或已完成的分享保留原目录。名称会处理跨平台保留字、非法字符、Unicode 和大小写冲突。同名新版本与发布时出现的目标冲突会追加稳定后缀，不覆盖已有文件。

程序只取原始二进制下载地址，不使用媒体转码地址。默认同一时刻只下载一个文件；大于 8 MiB 的文件默认用 4 个 HTTPS Range 连接并发下载固定 8 MiB 的分块，连接只领取已验证前缀之后有限窗口内的分块。连接数可用 `config --connections <1-8>` 或全屏界面设置页修改，从下一个文件开始生效；设为 1 时与早期版本一样单连接顺序下载。所有连接共用同一个已核对版本的签名地址，地址只保存在内存中，最长 30 秒或失效时只刷新一次，并重新核对副本身份、大小和 GCID；发现版本变化立即停止全部连接。


同时下载的文件数可用 `config --files <1-5>` 或设置页修改，默认 1。实际生效值还受账号等级限制：程序只读查询会员信息，会员最多 5 个，免费账号或暂时读不到等级时只能 1 个，设置页与 `status` 会同时显示配置值、等级与实际生效值。扫描与云端转存始终逐个进行：每个文件转存前先占用一个名额，下载、校验与发布完成（或失败、取消、中断）后才释放，因此云盘中尚未交付的副本最多与名额数相同，正在下载的副本永远不会被回收。所有在途文件合计最多 8 个 CDN 连接，每个文件分得 ⌊8 / 在途文件数⌋ 个（至少 1 个）；有新文件加入时，已有连接完成当前分块后不再补足。取消一个文件只停止它自己；暂停队列、退出程序或任何账号级暂停（登录失效、流量不足、限流、本地磁盘写满等）会让全部在途文件在安全点停止并保存断点。

部分连接遇到限流（429）时先把该文件的并发减半并按服务端的等待指引冷却，持续成功后逐步恢复；降到单连接仍被限流，或等待超过 60 秒时，才按账号限流暂停。流量额度不足（402）立即停止。单个连接断开或停滞时，该分块从已接收处由其他连接继续；同一分块连续失败 3 次，或全文件连续 6 次失败且期间没有分块完成时，才计入文件级的有限重试。服务端忽略范围、`Content-Range` 不符或响应超出范围时，不追加这些数据：该文件改为单连接顺序模式并从头下载，此后再次出现则报告范围不符；显式 `retry` 会清除顺序模式，自动重试保留。错误范围、截断、版本变化和摘要不匹配都不能成为完成记录。

临时文件与任务版本绑定。检查点包括连续已验证前缀（偏移与前缀 SHA-256）和前缀之后最多 16 个分块区间（各自的起点、已写字节与 SHA-256）；保存时先 `sync`，再把已完成的队头分块从磁盘读回、与接收时的摘要比对后并入前缀，最后在一次写入中保存，崩溃时检查点不会声明未落盘的字节。恢复时重新读取并核对前缀，不一致则从头开始；前缀有效时逐个读回区间，只丢弃对不上的区间，不信任 UI 上次显示的进度。只截掉超过文件大小的部分，前缀之后已核对的区间保留。GCID 仍按原算法顺序计算，输入是逐块核对过的磁盘数据；完成后与服务端值比对并整文件读回校验，同时保存本地 SHA-256；本地 SHA-256 不等于服务端提供了同算法摘要。

正式发布前保存目标、尝试号、暂存文件身份与完整摘要；每次冲突换路径都先提交新意图。macOS 使用相对目录句柄和不覆盖重命名。恢复核对最后一次已保存路径、卷/文件身份及完整摘要，不能只因一个用户已有文件内容相同就认领成功。Windows 的对应原生句柄实现仍需实际运行验收。

已有转存副本时，恢复优先按账号内精确 ID 读取，不重新要求原分享仍可访问。只有明确的文件不存在类别才允许在有限预算内重新转存同一源版本；普通 404、权限失败和网络错误不证明副本已丢失。无法唯一确认的写入或发布保留记录并等待核对，不直接重发或扩大删除范围。

临时文件或目录被替换时保留现有资源；不要直接编辑任务数据库绕过保护。取消停止调度，不撤销已经发生的交付，也不赋予未交付副本清理资格。

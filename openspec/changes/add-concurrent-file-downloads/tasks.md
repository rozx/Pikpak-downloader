# Tasks

按依赖顺序执行。本变更建立在 `add-parallel-segment-download` 之上，开始第 2 组之前该变更的实现任务应已完成（真实环境验收 5.2 可以并行）。第 1 组是验证门槛：P3b 不通过时停止本变更并记录原因，默认值 1 的行为不受影响。用户于 2026-10-15 同意在 P3b 完成之前先实施第 2–5 组（P3a 已通过）；P3b 不通过时这些实现保留在默认值 1 下不生效，并按 1.3 回到评审。各组区分真实接口、模拟服务和实际操作系统三类验证，不用其中一种代替另一种。复合任务只有实现与验收全部满足才勾选。

## 1. Feasibility

- [x] 1.1 P3a 账号等级：在 `spikes/concurrent-files/` 编写只读验证程序，用本工具已授权的会话尝试会员信息类接口（如 `/drive/v1/privilege/vip`），并记录 `/drive/v1/about` 的容量上限能否作为后备依据；记录字段、取值与失败表现。验收：结果按 design.md 决策 1 判定并记录到 Evidence；输出不含账号资料、令牌或签名地址；找不到可靠依据时明确记录“按免费处理”。结果（2026-10-15）：`/drive/v1/privilege/vip` 以现有授权返回 `type`、`status` 与 `expire`，会员测试账号为 `platinum`；按 Evidence 中的等级规则判断，失败或格式不符按未知处理。
- [ ] 1.2 P3b 多文件并发：在会员测试账号上，用 2、3、5 个不同的保留副本同时下载（每个文件 1 个连接、合计不超过 8），各运行 3 次，记录合计吞吐、每个连接速率与 429/403/402 次数，以及服务端是否拒绝同时下载。验收：结果按决策 1 判定并记录到 Evidence；测试副本由用户指定或取自任务库中保留的副本；不写本地文件、不输出文件名。
- [ ] 1.3 汇总 P3a、P3b，确认会员上限（1–5）与等级判断方式。验收：P3b 不通过时停止本变更并记录原因；通过后才开始第 2 组。

## 2. Configuration and Account Tier

- [x] 2.1 配置键 `max_active_files`（1–5，默认 1）与共用校验，`config --files <1-5>` 写入并在 `status` 中显示配置值、等级与实际生效值。验收：拒绝 0、负数、非整数、带多余字符和大于 5 的值并保留原值；未设置时为 1；监听占锁时写配置按单实例规则拒绝。
- [x] 2.2 账号等级读取：按 1.3 确定的方式实现只读判断，会话启动时读取并每 10 分钟刷新，失败时沿用上次结果，从未成功时按未知处理；提供 `effective = min(配置值, 等级上限)`。验收：单元测试覆盖免费、会员、未知、刷新失败沿用、会员到期后降级；等级接口的错误不触发认证暂停以外的任何暂停。

## 3. Executor and Session

- [x] 3.1 下载池与名额：`Engine.step()` 只做扫描或“占用名额 → 检查副本 → 空间计划 → 转存”，之后把“下载 → 校验 → 发布”交给最多 N 个任务的下载池；发布中的文件也作为池任务进入；`nextFile` 跳过已在池中的文件；N = 1 时 `step()` 等待池任务完成后返回。验收：现有 engine、session、interruption、transfer 测试在 N = 1 下全部通过且不改断言；新测试覆盖 N = 3 时同时在途不超过 3 个、转存始终串行、名额在完成/失败/取消/中断时释放。
- [x] 3.2 池任务的错误分类：把 `step()` 现有的下载错误分类提取为共用方法，池任务按同样规则处理文件级失败、版本变化、限流、流量、本地空间、目标不可用与认证；任何账号级暂停都停止其余池任务。验收：用模拟服务覆盖每类错误各一次，结果与 N = 1 时一致；账号级暂停后所有在途文件都保存了可核对的检查点。
- [x] 3.3 云端容量：名额在转存前占用；下一个文件放不下时进入等待空间并释放名额；在途副本不成为回收候选；在途文件完成后其副本按现有规则成为候选。验收：模拟服务测试覆盖“只能再容纳一个副本”和“在途文件完成后腾出回收空间”两个规格场景，且在途副本从未被删除。
- [x] 3.4 会话跟踪多个执行项：串行步骤与池中文件各自有中断控制器；取消文件只中断目标，取消分享中断其全部在途文件，暂停队列与中断停止全部执行项并等待检查点保存；进度节流改为按文件分别计算。验收：会话测试覆盖取消其中一个文件时其他文件继续、取消分享、暂停与继续、Ctrl+C 有界停止，以及多个文件的进度事件互不挤占。

## 4. Connection Budget

- [x] 4.1 `ConnectionBudget`：总量 8，下载池登记在途文件，份额为 `max(1, ⌊8 / 在途文件数⌋)`；分段协调器新建连接时取每文件设置、限流后并发与份额的最小值；份额变小时不中断已有连接、只停止补充。验收：纯逻辑测试覆盖份额计算与登记注销；协调器测试证明第三个文件加入后，前两个文件不再补连接，最终合计不超过 8；小文件各占 1 个预算。

# Design

## Context

动机与产品范围见 [proposal.md](proposal.md)，可观察行为见六份能力规格。当前仓库只有 `LICENSE` 和 OpenSpec 初始化文件，没有可复用的认证、下载、持久化或测试实现。下文的模块与数据结构均为拟议设计，不是对现有代码的描述。

访谈已明确：两平台独立运行；云盘仅作中转；只回收本工具已成功交付的副本；清理资格不取决于本地文件之后是否仍在；重复制分享进行增量扫描；同名新版本保留旧文件；单文件有限重试；缺码等待完整文本补充；浏览器授权优先、密码登录可作备选。

资料证据与尚未验证的能力分开记录：

| 依据 | 已知事实 | 不能据此推断的能力 |
| --- | --- | --- |
| [PikPak 官方 FAQ](https://mypikpak.com/en-US/faq) | 回收站继续占容量；永久删除是独立权限；PAT 不提供永久删除权限；官方 CLI 提供浏览器授权 | 我们的独立客户端必然能取得同样授权或删除权限 |

## Goals / Non-Goals

**Goals:**

- 给每次云端写入建立可核对的意图与结果，防止重复转存和错误资源接管。
- 让文件的云端身份、源版本、下载进度、正式交付和清理资格形成完整可追踪链路。
- 在单机、单个活动账号与一个队列执行器的边界内实现可靠恢复；平台适配不泄露到调度策略中。

**Non-Goals:**

- 不承诺服务端不存在的能力，也不在接口验证失败时自动缩减已确认的产品行为。
- 不实现目录镜像、长期备份、跨设备状态同步或多设备对同一中转区的协调。
- 不在本次规划交付中建立应用骨架、安装业务依赖或运行真实账号写操作。

## Decisions

### 1. 接口验证是实施的第一阶段

采用“先验证关键链路，再实现业务流程”的任务顺序。下表是阻塞后续集成的验收条件，不是可以延期解决的开放问题。实施阶段在本文件相应行记录脱敏证据、通过/失败和日期；当前全部为待验证。

| 编号 | 必须取得的证据 | 未通过时的行为 |
| --- | --- | --- |
| G1 | 独立客户端可登录、确定账号身份、刷新会话，并取得读取、转存、查询容量、对指定 ID 永久删除的能力；验证浏览器路径，不可行则验证密码路径 | 不使用官方 CLI 或仅有 PAT 的路径冒充完整方案；两种登录均不可行时阻塞实现并报告接入限制 |
| G2 | 多页、多层分享能枚举单个子文件的大小、身份和版本；能只转存该文件；异步结果能精确映射到新建副本；请求响应丢失后能核对；原分享失效后按账号副本读取；能区别权限失败与确定不存在；删除后容量可重查 | 不转存整个超大父目录，不用同名匹配归属；保留“大分享、小云盘”要求并说明阻塞点 |
| G3 | 可区分同大小内容替换、改名和未变化版本；能校验大小/完整覆盖/版本，明确服务端摘要算法及可用性；验证 URL 刷新、Range 响应和版本变化 | 不把文件名、大小或未知算法值当可靠版本；无法形成可靠版本识别和交付判据时阻塞集成 |
| G4 | 发行目标上的稳定剪贴板快照、系统凭据存储、SQLite 事务、进程互斥、路径规则和不覆盖文件发布可工作；本次发布的文件身份在中断后可核对 | 不仅凭交叉编译通过宣称平台支持；修复平台适配并实际验证 |

测试账号中的新建、下载、修改与删除样本必须属于实施阶段明确指定的测试资源；本次文档授权不包含对现有云盘资源的操作。记录响应字段和错误类别时去除所有凭据及签名链接。

替代方案是先根据社区 SDK 完成主流程再处理兼容问题。由于逐子文件转存、资源归属和定向删除直接决定本项目能否成立，该方案的返工风险更高，故不采用。

### 2. 独立 Go 程序与少量适配模块

实现默认采用 Go 和本地 SQLite；锁定的 Go 版本、SQLite 驱动和系统库版本在 G4 通过时记录。应用发布目标为 macOS `arm64`/`amd64`、Windows `amd64`/`arm64`；平台支持需逐目标验证后声明。使用原生系统能力或随产物打包的依赖，用户不需要额外安装开发语言运行时。

建议入口命令名为 `pikpak-downloader`，避免与官方 `pikpak` 冲突。此命名以及以下模块名称属于实现默认，不是访谈中的用户命名要求。

| 模块 | 拥有的职责 | 不拥有的职责 |
| --- | --- | --- |
| CLI / 运行协调器 | 配置、生命周期、进度汇总、单实例锁 | 解析 API 响应中的服务端细节 |
| 剪贴板适配器与解析器 | 系统复制事件、完整文本解析、输入规范化 | 下载或空间清理决策 |
| 队列与状态库 | 状态转换、唯一约束、重试预算、恢复意图 | 网络协议和密码保存 |
| PikPak 适配器 | 登录、分享枚举、转存核对、容量、文件元数据、下载地址、定向删除 | 决定哪些文件已满足清理条件 |
| 下载器与文件发布器 | 传输、版本绑定续传、校验、安全路径和正式落盘 | 选择待删除的云端资源 |
| 容量管理器 | 容量判断、候选筛选、最旧优先计划、删除后核对 | 清空账号或接管既有文件 |
| 受保护凭据存储 | 认证令牌、分享访问秘密 | 普通任务查询和进度历史 |

其他可行语言不改变这些边界。选择 Go 是为了独立命令行产物和显式可取消的网络操作；SQLite 相比整份 JSON 状态更适合唯一约束、分页查询、事务提交和崩溃恢复。具体库版本必须通过 G4，不预先假定第三方剪贴板库能检测“再次复制相同文本”。

### 3. 单执行器与持久化状态模型

首版允许监听与网络执行并行，但同一任务库只有一个执行器，同一时刻最多一个云端转存/文件下载流水项。这样分享仍可分批完成，也避免多个任务争用云端预留容量。以后增加并发需要显式引入容量预留，而不能只增加协程数。

| 记录 | 关键字段或约束 |
| --- | --- |
| 账号 | 服务端稳定账号 ID、凭据引用、授权能力状态 |
| 分享请求 | 账号 ID、规范化分享 ID、首次接收时的固定输出根、最新资料引用、`requested_revision`、`attempted_revision`、取消标记；账号与分享唯一 |
| 扫描世代 | 分享 ID、领取的请求版本及不可变资料引用、枚举范围及完整标志、分页/目录进度；不完整不能推导移除 |
| 文件版本 | 分享 ID、源文件稳定 ID、可靠内容版本、源路径、大小、状态、累计尝试数；身份与版本唯一 |
| 云端副本 | 精确远端 ID、所属账号、关联的源版本、实际副本版本/内容指纹、创建操作 ID、归属证据、预期父目录、清理状态及使用者引用 |
| 本地交付 | 继承的固定下载根、保留目录映射、临时路径、目标路径、发布尝试号及可核对文件身份、持久化字节检查点及前缀摘要、完整文件摘要、验证方式、`completed_at` |
| 外部操作意图 | 类型、目标身份、预期版本、已知任务 ID、状态、时间；不保存令牌、密码或签名 URL |
| 执行状态 | 全局暂停原因、可恢复条件、错误分类；错误中敏感字段脱敏 |

普通数据库保存在本机用户应用数据目录，下载目录可位于另一卷；数据库不跟随下载目录移动。认证令牌及分享访问秘密放入系统受保护存储，数据库只存引用。库结构带版本号，升级前备份任务库；备份也作为私有用户数据管理。

分享访问资料更新采用“先保存新的受保护条目，再事务切换引用”的顺序。每个请求资料版本使用新的不可变引用，不能就地覆盖正在扫描的资料；受保护存储成功后，SQLite 才能提交相应请求版本并确认已接收。数据库提交失败则原引用保持不变，新条目成为可核对的孤立资料；回收它之前检查分享、活动扫描和未完成操作均无引用。重启时出现不可读引用，只阻塞需要该资料的阶段。认证令牌刷新与分享资料更新分开处理；服务端已轮换令牌而本地保存失败时暂停并要求恢复授权，不静默继续使用旧令牌。

SQLite 使用支持持久提交的同步设置和短事务，不在等待网络时持有写事务。进程生命周期持有系统互斥锁；不能用“锁文件存在”判断进程仍活着。状态查询只读；登录、登出、配置修改、`retry` 和 `cancel` 等写命令在 `watch` 占锁时明确拒绝，提示先 Ctrl+C、执行修改、再运行 `watch`。这避免为首版增加常驻服务和跨平台控制通道。

逻辑文件状态如下；等待与失败原因单独保存：

```text
discovered --> ready --> saving --> awaiting_remote --> downloading
                  |                                      |
                  v                                      v
            waiting_space                            verifying
                                                         |
                                                         v
                                                     publishing
                                                         |
                                                         v
                                                     completed

transient_error --> retry_wait --> previous_stage
retry_exhausted --> failed --> explicit_retry --> ready
unknown_write_result --> reconciling --> known_state / needs_attention
unfinished --> cancel_requested --> reconciled --> cancelled
cancelled --> explicit_retry --> ready
```

`completed` 是交付事实；云端副本另外维护 `retained / deleting / deleted / protected` 状态。清理不撤销本地完成记录；本地文件之后变化也不改变交付事实。目录和分享显示聚合状态，不能因其中一个文件完成而将整个分享置为成功。

`cancelled` 表示停止调度，不是完成或删除。取消分享会停止其后续扫描及未完成子任务，已完成子项保持完成；取消文件仅停止该文件版本。分享和文件各自保留取消标记，重启读取旧剪贴板或普通重扫描不会清除；`retry` 才显式解除选中范围的取消。新的内容版本不是同一个被取消文件版本，但取消整个分享时也不会自动发现新版。若取消时有待核对的发布，先确认是否实际已交付，已发生的完成事实不能倒退为未交付；未知远端写入意图继续保留并核对，不能借取消跳过必要核对或授予清理资格。

### 4. 剪贴板接收与增量扫描

macOS 和 Windows 适配层读取系统提供的内容变化信号；仅比较文本摘要会漏掉再次复制相同内容，因此不能作为唯一检测依据。启动读取一次当前文本，后续默认每 500 毫秒检查变化标识。每次按“读取变化标识、读取文本、再次读取变化标识”取得稳定快照；前后不一致时丢弃并有界重试，不能把新文本配上旧标识。无访问权限、延迟呈现、暂时为空和短暂占用按平台适配结果处理，不能统一判定为已读取；持续故障显示监听异常，不影响已有下载。

根据变化标识只能判断内容更新，不能还原在两次读取间被覆盖的文本；标识差值也不等于遗漏的复制次数。产品只确认实际取得并持久化的输入，终端立即显示已接收的分享及任务 ID，说明中要求未见确认时重新复制。输入提交失败时不推进该快照的已处理游标，以便在仍可读取时重试；用户已经覆盖的未确认内容无法保证补收。这是系统剪贴板采样的边界，不用启动额外剪贴板历史服务来隐式扩展产品范围。

解析器只接受验证支持的分享主机、路径格式和明确的链接/提取码对应关系，不能让任意剪贴板 URL 被作为请求目标。跟随已支持的别名或跳转时仍检查主机范围。分享 ID 用于去重，提取码不是身份的一部分；新的完整文本可以更新错误或缺失的访问资料。多链接文本只接收配对明确的条目；不保存原始文本，不跨复制事件拼接提取码。

请求首次接收时把账号和下载根固定到分享记录，后续增量文件继承该根；配置更改只影响新分享。每次已接收输入在同一事务中递增 `requested_revision` 并切换到已保存的新资料引用。没有活动扫描时，执行器原子领取最新请求版本及其资料引用，并记录 `attempted_revision` 和活动扫描世代；该世代在完成或失败时只更新自己的结果，不能清除更大的请求版本。若 `requested_revision > attempted_revision`，下一轮合并领取当时最新版本，因此仍至多有一个活动扫描和一个待合并需求。

进程中断后先恢复未结束的扫描世代；扫描失败有独立的有限尝试记录，不能因为其版本未成功就立即无限重扫。旧资料导致的错误只能影响使用该资料的扫描，不能把后来已接收的新资料标记无效。持续不变的剪贴板不发起扫描；不会在用户没有再次复制时定时检查分享更新。

枚举通过队列逐页、逐目录展开，并持久化或通过幂等重扫恢复；记录已访问目录身份和页标识以终止异常循环。每发现一个可靠文件版本便幂等合并，不需要把完整大分享清单保存在内存。扫描中断标记为不完整，可重试，不能把未发现的旧条目当成已删除。

去重范围为账号、分享、源文件 ID 与内容版本，不做跨不同分享的内容全局去重。内容版本必须通过 G3；同名同大小不够，修改时间单独也不能被假定可靠。只有名称改变、或原本地文件已移走时，不重新交付同一完成版本。新版独立排队，旧版记录不被改写。再次复制只触发扫描或补充访问资料，不自动重置耗尽的失败重试预算；用户通过 `retry` 开启新的有限尝试周期。

### 5. 逐文件转存及云端归属

每个文件开始时先检查账号、目标磁盘、大小与云端容量，再创建持久化转存意图。G2 必须选择一种确有证据的关联方式：服务端幂等键/可查询操作结果，或能通过独有目标容器和精确结果核对的新建副本。隔离文件夹名称本身不足以证明归属。

只有服务端操作结果证明副本由本工具新建并能映射到源版本，才登记为工具拥有。若接口返回账号中已存在的文件，不能因它出现在响应中就取得删除资格。请求未知时进入 `reconciling`，不能马上重发。仍无法唯一确认时显示需人工处理，并保留操作意图以供核对。

等待异步转存完成后核对结果文件大小、源版本与可读取状态，之后获取下载地址。源文件 ID/版本与新副本 ID/版本分别保存，不能假定两者相同；它们的关联及可比较的内容指纹由 G2/G3 确认。转存等待默认最长 10 分钟，指数退避且单次间隔最多 30 秒；到期先核对，再进入等待处理，不把超时解释为“肯定没转存”。若下载前版本已经变化，停止该项并重新扫描，不能将变化内容登记到原版本。

中转容器和归属记录按安装实例及账号隔离。首版不接管其他安装或设备的中转资源；用户若移动、修改云端候选使它不再满足登记条件，回收时将其标为 `protected` 并报告。空中转目录可保留；首版不递归清理目录，以免未知子项被连带删除。

恢复按所处阶段选择数据源：尚未取得副本的条目需要原分享访问；已有副本则先通过当前账号及精确副本 ID 核对大小与副本版本、取得下载地址，原分享失效或提取码变更不单独阻止这一步。已知副本被可靠确认不存在时，才尝试用仍可访问的同一源版本重新转存，新的转存消耗原任务的有限重试预算并先记录新意图；403、网络错误、语义不明的 404 不能作为确定不存在。若源版本也消失，保留失败及临时文件；若只剩新版本，旧项不得拼接新版，新版本由扫描单独建立。

### 6. 校验、目标路径与交付提交

每个分享在首次接收时固定输出根，首次分配分享子目录时使用清理后的标题加分享 ID 短后缀并持久化，避免不同分享同名冲突；后续标题改变或重复制不重算已分配目录。子路径尽量保留目录层级，名称映射持久化；处理 Windows 保留名称、非法字符、大小写/Unicode 规范化碰撞、路径长度以及符号链接或目录联接。无法保证目标位于下载根内时只拒绝该条目。

新文件遇到已有目标时追加稳定任务/版本后缀，必要时再追加序号；目标预分配并持久化，重试复用。正式发布使用目标平台上的“不覆盖已存在文件”操作，不能先检查存在再用可能覆盖的普通重命名。发布时出现竞态则分配新后缀，必须先提交新的发布尝试号和目标路径，再执行下一次发布；不能只在最终完成事务中追记新路径。

临时文件位于目标卷内的专用临时目录，绑定账号和源版本。首版使用单连接顺序下载；续传必须验证 Range 状态、起始位置、总长度和内容版本。返回 200 整体内容或不匹配范围时从头重启未完成文件，不能追加。签名 URL 失效可以更新地址，但不能把 HTTP 错误页、另一版本或压缩转换后的字节直接作为原文件续传。

下载检查点先刷新有效前缀的数据，再事务保存字节偏移和该前缀的摘要。恢复时重新计算并核对前缀摘要；文件更短、内容不匹配或检查点缺失时从头下载，文件更长时仅保留已验证检查点以内的数据。普通 UI 进度不是已持久化检查点。这样即使服务端没有可用整文件摘要，也不会把停机期间被改动的旧前缀拼入新下载。

最低交付判据为：服务端已确认大小、完整字节覆盖、稳定内容版本，及本地可读的完整文件；记录本地 SHA-256 用于后续恢复核对。若服务端提供已验证算法的内容摘要，必须比对。PikPak 的某个字段名包含 `hash` 不代表它就是标准整文件摘要，需 G3 验证；无法可靠判定源版本则阻塞该文件，而不是静默降级。

跨资源提交次序：

1. 下载结束，完成所有适用校验，刷新临时文件数据；暂不赋予清理资格。
2. 事务保存 `publishing` 意图，包含版本、预期大小、摘要、可核对的暂存文件身份、发布尝试号及本次目标。文件身份采用 G4 验证的同卷发布标识，例如可稳定核对的卷 ID/文件 ID，不仅是路径和内容摘要。
3. 不覆盖地发布到本次目标，完成平台支持的持久化操作。若目标冲突，每次重新选择路径都返回步骤 2；旧目标不再是本次发布的恢复依据。
4. 事务写入正式路径、验证方式和 `completed_at`，将文件标记完成；只有此事务成功后才成为回收候选。
5. 若在 2–4 之间中断，恢复时核对最近已提交发布尝试的临时/正式路径、文件身份及摘要，能证明本次发布已交付才补全完成记录。同路径上仅内容相同的他人文件不能证明发布成功；身份或结果无法核对时保留文件及云端副本并等待处理，不猜测成功，也不另分配新副本来掩盖未知结果。

用户之后自行移动、修改或删除本地成果不影响历史完成记录。恢复核对只适用于尚未提交完成的交付，不得扩展为每次清理都重查已完成的本地文件。

### 7. 空间计划与定向回收

每轮以当前文件大小及服务端必要开销计算需求，已确认的同一文件中转副本可复用，不重复计入新转存。首版不预存多份尚未下载的批次。先确认本地可以接收，再考虑云端清理，避免本地根本无法写入时仍删除云端文件。

如果文件大于云盘总容量，直接标记无法容纳；如果空闲容量加全部合法候选仍不足，让该文件等待，不进行徒劳删除。调度可尝试其他能容纳的文件；所有文件都等待时进入有界容量重查并显示原因，禁止忙循环。默认空间等待重查周期 60 秒，用户重启执行也立即重查。

候选条件同时满足：当前账号、登记为工具新建、对应版本交付已完成、无活动使用者、远端 ID/版本/管理位置仍匹配。按 `(completed_at, 稳定副本 ID)` 升序逐个回收，删除前复核条件并持久化意图。若共享同一远端 ID 的多个内部引用尚有未完成使用者，即使部分引用完成也不能删除。

使用 G1/G2 实测通过的定向永久删除接口；若服务端要求先移入回收站，只操作选定 ID，之后对同一 ID 永久删除。不调用全局清空回收站，也不按路径或名称批量删除。对候选级冲突或明确不可删错误记录原因并跳过；权限失败暂停执行；结果未知时先核对，不继续选更多候选。

每次删除后重新查询存在性及容量，只有看到可用容量满足需求才继续转存。默认最多等待 60 秒让容量反映变化；超过后进入等待，不推算“已删除字节”等于立刻可用字节。下次恢复先核对同一删除意图，禁止为未知结果扩大删除范围。

### 8. 有界失败恢复与终端体验

默认每个文件级临时错误最多重试 3 次（初次尝试之外），采用带抖动的指数退避，遵守服务端可用的重试指引。尝试预算持久化；显式 `retry` 才开启新的预算。转存及删除的未知结果进入核对流程，不与普通幂等读取共用盲目重试。

| 错误类别 | 行为 |
| --- | --- |
| 缺码/错误提取码 | 分享等待新的完整文本，其他分享继续 |
| 分享明确失效、源文件不可用 | 记录条目或分享错误，其他工作继续 |
| 临时下载/读取失败 | 有限退避；耗尽后失败，保留可恢复文件和云端副本 |
| 云端存储不足 | 使用空间计划；不可回收则等待，尝试其他可容纳文件 |
| 认证刷新失败/必需权限缺失 | 全局暂停执行，监听继续；提示停下 `watch` 重新登录 |
| 本地磁盘不足/路径卷不可用 | 暂停执行并保留进度；修复后重新启动 `watch` 核对恢复 |
| 状态库写入失败 | 暂停执行；不能承诺新输入已接收，明确显示接收失败 |
| 流量配额耗尽/限流 | 等待相应条件或退避；不触发云端清理 |

基础命令采用 `login`、`logout`、`watch --output <目录>`、`status [任务ID]`、`retry <任务ID>`、`cancel <任务ID>` 及配置入口。任务 ID 可明确指向分享或文件，操作输出应说明范围；`retry` 允许恢复选中范围的失败/取消工作并保留已成功版本，`cancel` 仅停止未完成工作，不删除文件或释放未交付副本的保护。`watch` 重新启动时核对阻塞条件并恢复满足条件的执行，无需另建后台恢复服务。查询命令在执行期间只读；其他写命令遵守单实例规则。

全局暂停原因必须关联实际阻塞条件及受影响任务。目标卷永久不可恢复时，用户可以先停止监听、取消这些任务，再重新启动；若无其他任务需要该目标，相关路径暂停不应继续阻塞队列。账号失效、状态库不可写和未完成外部核对仍按各自规则处理，不能被取消另一个任务清除。取消之后的残留资源及保留原因可由 `status` 查看。

Ctrl+C 停止接收新工作，取消可取消请求并刷新有效进度；在有限退出等待后仍不确定的外部操作保留意图，下次核对。终端显示文件与分享聚合状态、进度和下一步操作，不输出提取码、认证信息或签名下载地址。输入去重历史不是任务审计日志的替代品，重要状态转换均有脱敏记录。

## Risks / Trade-offs

- 独立客户端的授权或接口能力不足 → 以 G1–G3 作为首批任务，失败时报告并重新评审，不能默默依赖官方 CLI、PAT 或整目录转存。
- 接口变更、验证码或服务端限制 → PikPak 适配器隔离协议，保存脱敏契约样本；需要用户交互时暂停，不绕过验证。
- 云端回收有不可撤销效果 → 精确 ID、来源证明、成功交付事实、删除意图和容量复查；不使用全局回收站清空。
- 下载失败副本长期占据空间 → 遵循“不删除未交付副本”，公开等待原因及重试入口，接受可能需要用户自行处理的结果。
- 本地交付之后用户删除成果 → 按用户选择仍可回收云端，本工具不是长期备份；在使用说明中解释这一行为。
- 单执行器吞吐有限 → 先保证恢复与容量规则；并发优化属于后续变更，不改变首版完成性目标。
- 两平台原生凭据、锁和文件发布语义不同 → G4 和实际平台烟测覆盖，不能只靠编译或模拟测试。
- 快速连续复制可能覆盖尚未读取的剪贴板文本 → 只确认持久化成功的输入，使用稳定快照、即时入队反馈和重新复制指引，不声称系统变化计数包含历史内容。
- 断电时文件系统与数据库不能一次提交 → 持久化交付意图、原子不覆盖发布和恢复核对；磁盘不支持所需语义时说明限制。
- 云端资源可能被其他客户端修改 → 操作前校验身份、版本及位置，发现冲突即保护；首版不协调多个设备对同一中转区的并发修改。

## Migration Plan

这是首个业务版本，无旧业务数据迁移。实施顺序为：G1–G4 验证与记录、状态/身份基础、单文件端到端链路、嵌套分享与空间回收、剪贴板和终端集成、两平台验证及打包。

上线前使用明确指定的测试资源验证成功与中断路径，再交付独立产物和配置说明。停止使用时退出 `watch` 即停止自动行为；卸载不应自动删除本地成果、任务数据或遗留云端副本。升级前保留任务库备份，旧版本遇到更高结构版本拒绝写入；首版不提供自动降级或自动恢复历史备份后执行的功能，因为备份可能遗漏之后已发生的远端写入。人工回退必须先核对外部状态和已交付版本，再恢复执行，不能把未知结构当成空队列。丢失归属记录后的云端文件不再自动接管或清理。
